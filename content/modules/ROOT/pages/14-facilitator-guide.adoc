= Facilitator Guide
:navtitle: Facilitator Guide

For facilitators provisioning workshop environments ahead of class.
Participants can skip this page.

Division of labor: the gitops path deploys the workshop
prerequisites; the fleet scripts install SAW per
cluster; participants run xref:05-module-03-deploy-secure-agent-workspace.adoc[Module 3]
only when self-deploying. The fleet scripts loop that module's documented
procedure and never duplicate fork logic.

Do not provision SAW ahead of time when the class is meant to run the
lengthy manual setup: deploying SAW with the fleet script removes
xref:05-module-03-deploy-secure-agent-workspace.adoc[Module 3] from the
extended track, because that module is the documented manual install.
Setup the clusters with the fleet automation scripts only when participants should skip those steps.

== Provision the clusters

One-time shared assets, reused for every cluster:

[source,bash,subs="attributes+"]
----
mkdir -p ~/git && git clone --branch {saw_repo_branch} \
  {saw_repo_url} ~/git/{saw_repo_dir}
cp ~/git/{saw_repo_dir}/values-secret.yaml.template ~/values-secret.yaml
cd ~/git/{saw_repo_dir} && make generate-keys
----

[IMPORTANT]
====
In a facilitator-led workshop, Vault seeding is a FACILITATOR step — the
facilitator seeds the shared provider keys once per cluster; participants
never seed. Self-paced participants running the modules alone seed their own
keys in module 3. The shared provider keys cover every cluster and every
participant. Edit
`~/values-secret.yaml` once: set the NVIDIA NGC API key for the default
`nvidia/nemotron-3-super-120b-a12b` model and a Tavily key for web search,
each in a readable file (for example `~/.ngc-api-key`,
`~/.tavily-api-key`). Seed them into each cluster's Vault with the fork's
seeding script — run it once per cluster, after that cluster's `saw-gitops`
tree has converged (the script reads the `vault-init` Secret the
vault-config Job creates and tells you if the tree is not there yet):

[source,bash,subs="attributes+"]
----
KUBECONFIG=<cluster-kubeconfig> ~/git/{saw_repo_dir}/scripts/seed-vault.sh
----

The gateway-side providers hold the keys and participants never see them —
no participant step prompts for a model key on the SAW track. Each
participant's workstation seeds its *own* SSH key (module 3, in the
clone-and-secrets flow): the SSH key is
always a per-user step, never a shared one. Module 8 needs no facilitator
key — participants obtain their own Model-as-a-Service key and enter it at
install time.
====

The workshop deploys declaratively: the RHDP order's gitops path deploys the
workshop chart (`{automation_repo}/argocd`), whose templates create the
`saw-gitops` root application (the SAW tree: operators, Vault, External
Secrets, Virtualization, Keycloak, governance, the BOM, and the per-user
workspace VMs) and the `module-7-prereqs` child (the capstone environment)
directly in the cluster's `{gitops_namespace}` instance. On a cluster
without the order pointer, apply both once:

[source,bash,subs="attributes+"]
----
oc apply -f {automation_repo}/argocd/saw/root-application.yaml
make -C {automation_repo} capstone-bootstrap
----

[CAUTION]
====
When the GitOps deployment has already provisioned SAW, module 3 is already
done — participants keep that time for the agent modules. Tell them so in
the welcome notes.
====

Then watch each cluster converge: every `saw-*` application Synced and
Healthy, the workspace VM `Running`, and the per-user prepare Job `Complete`:

[source,bash,subs="attributes+"]
----
oc get applications -n {gitops_namespace}
oc -n saw-<user> get virtualmachine <user> \
  -o jsonpath='{.status.printableStatus}'
oc -n saw-<user> wait --for=condition=complete \
  job/<user>-prepare --timeout=3600s
----

Seed the shared provider keys (the script above) once the tree has
converged — the ExternalSecrets resolve them on their next refresh.

`fleet-install.sh` (the Validated Patterns install loop) remains the
fallback for clusters provisioned without the order pointer; `fleet-status.sh
--gate` exits non-zero if any cluster in `clusters.csv` is not ready.

== Verify every cluster

[source,bash]
----
./{automation_repo}/fleet/fleet-status.sh
----

Shows Argo CD Application sync/health, the SAW VM phase, the setup Job, and
the workshop namespaces per cluster. Any cluster whose Applications are not
Healthy or whose VM is not Running needs attention before class; use the
installation diagnostics in xref:05-module-03-deploy-secure-agent-workspace.adoc[Module 3].

For a single cluster, poll just the current `oc` context with
`fleet-status.sh --current`. Before participants arrive, gate the whole
fleet — it exits non-zero if any cluster is not ready:

[source,bash]
----
./{automation_repo}/fleet/fleet-status.sh --gate
----

== Day of class

* Both checkouts and participant tooling are ready per
  xref:02-details.adoc[Prerequisites and Environment].
* With SAW provisioned ahead of time, participants skip Module 3 and start at
  xref:03-module-01-basic-openshell.adoc[Module 1], or jump straight to the
  xref:09-module-07-sre-capstone.adoc[capstone].
* When the class runs the manual setup instead, participants install SAW as
  the Module 3 prework before class and the extended-track total grows by
  90-150 min.
* Console URLs come from the RHDP orders.
